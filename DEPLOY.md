# Deploying Agri-Yield Pro

Frontend → **Vercel** · Backend → **Render** (free, Singapore) · Database → **Neon Postgres** (free).
Every push to `main` redeploys both automatically.

## 1. Database (Neon)
1. Sign up at <https://neon.tech> → create a project (region: Singapore / Asia).
2. Copy the **connection string** (`postgresql://…`). You'll paste it into Render.

## 2. Backend (Render)
1. Sign up at <https://render.com> with GitHub.
2. **New → Blueprint** → choose this repository. Render reads `render.yaml`.
3. Fill in the secret values it asks for:
   | Key | Value |
   |---|---|
   | `DATABASE_URL` | Neon connection string |
   | `FAST2SMS_API_KEY` | from fast2sms.com → Dev API (leave empty to keep test mode off: OTP will fail) |
   | `GOOGLE_CLIENT_ID` | optional, Google Cloud OAuth Web client ID |
   | `DATA_GOV_IN_API_KEY` | optional, from data.gov.in (faster mandi prices) |
   `SECRET_KEY` is generated by Render; `APP_ENV=production` hides test OTP codes.
4. Wait for **Live**, then open `https://<service>.onrender.com/api/health` → `{"status":"ok"}`.
5. If Render gave a different URL than `agri-yield-pro-api.onrender.com`, update it in `frontend/vercel.json`.

## 3. Frontend (Vercel)
1. Sign up at <https://vercel.com> with GitHub → **Add New → Project** → import this repository.
2. **Root Directory:** `frontend` · Framework: **Vite** (detected). Leave `VITE_API_URL` unset —
   `vercel.json` forwards `/api/*` to Render, so the browser talks to one origin.
3. Deploy, open the URL, create an account.

## 4. After the first deploy
- Google sign-in: add the Vercel URL to the OAuth client's **Authorized JavaScript origins**.
- Render's free plan sleeps after 15 idle minutes; the first request then takes ~30–60 s.

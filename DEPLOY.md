# Deploying Agri-Yield Pro

Frontend → **Vercel** · Backend + database → **Render** (free, Singapore).
Every push to `main` redeploys both automatically.

Live today:
- Site: https://agri-yield-pro-india.vercel.app
- API: https://agri-yield-pro-api.onrender.com (`/api/health`)

## 1. Backend + database (Render)
1. Sign in at <https://render.com> with GitHub and give Render access to this repository.
2. **New → Blueprint** → choose this repository. Render reads `render.yaml` and creates:
   - `agri-yield-pro-api` — the FastAPI web service
   - `agri-yield-pro-db` — a free PostgreSQL database; its connection string is wired into
     `DATABASE_URL` automatically (no password to copy)
3. Optional secrets it asks for (can be added later under the service's **Environment**):
   | Key | Value |
   |---|---|
   | `FAST2SMS_API_KEY` | fast2sms.com → Dev API (needed for mobile OTP) |
   | `GOOGLE_CLIENT_ID` | Google Cloud → OAuth *Web application* client ID |
   | `DATA_GOV_IN_API_KEY` | data.gov.in personal key (faster mandi prices) |
   `SECRET_KEY` is generated by Render; `APP_ENV=production` hides test OTP codes.
4. When it shows **Live**, open `/api/health` → `{"status":"ok"}`.
5. If the service URL differs from `agri-yield-pro-api.onrender.com`, update it in `frontend/vercel.json`.

## 2. Frontend (Vercel)
1. Sign in at <https://vercel.com> with GitHub → **Add New → Project** → import this repository.
2. Choose **frontend** as a single project (Root Directory `frontend`, preset **Vite**). No environment variables.
3. Deploy. `vercel.json` sends `/api/*` to Render and runs `api/agmarknet.js` in Mumbai (`bom1`),
   because data.gov.in only accepts requests from India.
4. If the Vercel project name differs from `agri-yield-pro-india`, update `MANDI_PROXY_URL` in `render.yaml`.

## 3. After the first deploy
- Google sign-in: add the Vercel URL to the OAuth client's **Authorized JavaScript origins**.
- **Free Render Postgres expires after 30 days** — upgrade `agri-yield-pro-db` (Render → the database → Upgrade) to keep data.
- Render's free API sleeps after 15 idle minutes; the first request then takes 30–60 s.

## Using another Postgres (Supabase, Neon…)
Set `DATABASE_URL` on the Render service yourself instead of the blueprint link:
- Use an **IPv4** connection string (Supabase: *Session pooler*; Neon: the pooled string) — Render cannot reach IPv6-only hosts.
- If the URL contains `[YOUR-PASSWORD]`, put the password in `DATABASE_PASSWORD` (no %-encoding needed).
- Test the string first on your computer: `venv\Scripts\python.exe db_check.py "<url>"` (asks for the password, hidden).

## Troubleshooting
| Symptom in Render logs | Fix |
|---|---|
| `Could not parse SQLAlchemy URL` | `DATABASE_URL` isn't a `postgresql://…` string — copy it again |
| `password authentication failed` | wrong/old password — reset it at the provider, copy fresh |
| `Network is unreachable` (IPv6 address) | use the provider's IPv4 / pooler connection string |
| Weather or mandi errors | weather loads in the browser; mandi needs `MANDI_PROXY_URL` set |
